How Asbuilt works

Three flows. Mail is captured whenever it arrives, the knowledge layer is rebuilt whenever mail changes, and a question runs through the assistant whenever the contractor asks. Every branch below is a decision the code actually makes — no summarised steps, no rounded-off logic.

01  When one email arrives

Per-message: ingest, dedupe, extract text, harvest identifiers

Runs for every UID pulled off IMAP. The rule is capture never fails: even a message the parser can't understand is stored and dealt with later. Two dedupe keys do the heavy lifting — Message-ID for the mail, sha256 for the bytes.

02  Once per batch — turning captures into knowledge

End of every refresh: what gets learned, what gets promoted, what gets thrown away

Everything in flowchart 01 was deterministic per-email plumbing. This is where mail actually becomes organised. Runs once at the end of every refresh.py, after all new mail is stored. No model calls here either — every decision is a rule applied against the captured corpus.

03  When a question is asked

Per-query: resolve, retrieve, clean, model, validate

Runs whenever the contractor types into the ask bar. The model is the last decision, not the first — everything before it is deterministic, and everything after it is a check on what the model returned. This is what makes an answer checkable: every citation is validated against the exact set of messages that were shown to the model.
